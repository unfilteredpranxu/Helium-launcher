## Verified production path

| Stage | Source and behavior |
|---|---|
| Generation | `crates/horizon-client-render/src/mesher.rs:1590`: `mesh`/`mesh_reusing` consume a 3x3 chunk neighbourhood, state/model tables, biome data and lighting. Reused `MeshScratch` holds the padded halo and masks; uniform air returns empty. Neighbour visibility hides internal faces. Baked models provide corners/UVs; offsets remain floating point. |
| Lighting/materials | `mesher.rs:1908` bakes tint, face shade and normal AO into RGB, with sky/block fixed-point light stored separately. `separate_ao` instead uses the high color byte for AO: shader-pack provenance is external and unsupported here. `quad_as` at `:2065` assigns the same layer/opaque flag to all corners and selects solid/translucent storage. |
| Sorting | `streaming.rs:998` calls `mesh_reusing`, then `sort_solid`. `mesher.rs:437` and `mesher/sides.rs:280` group whole quads by seven facing buckets and opaque/cutout parts, preserving corner order and coplanar ties. Axis cutouts are front-to-back. Metal's production path can group all opaque buckets before cutout buckets. |
| Optional packing | `mesher/packed.rs:1,203`: eligible grid quads become one 24-byte record; FULL records refer to appended four-vertex geometry, with padding. Packing is retained only when smaller. This is NOT an expanded vertex stream. `SectionMesh.solid` remains available alongside it. |
| Upload | `gfx.rs:5689` chooses packed slots or expanded solid bytes, uses arenas and shared quad indices, and separately handles translucent vertices/sorted indices. `gfx/upload.rs:1,97` copies into a reused staging belt and encodes GPU copies. |
| Drawing | `gfx.rs:5106` creates `[0,1,2,0,2,3]` per quad. Sides/visibility and CPU/GPU culling choose runs; arena offsets and camera-relative origins are external to the CPU vertices. The production terrain pipeline also has behavior absent from G02 (fog/fade, filtering/mips, HDR and sprite banks). |

`SectionMesh` (`mesher.rs:343`) directly provides expanded `solid`, `translucent`,
optional `packed`, side ranges, visibility, bounds, block-entity/light lists and
sprite-layer metadata. The sprite list is not a substitute for scanning all used
layers: `quad_as` records layers there when animated. The bridge scans the actual
solid vertices and reports one plus their highest unflagged layer.

Not in SectionMesh: section world origin, camera, projection, mesh revision,
normal-section versus tiled-LOD UV provenance, shader-pack/separate-AO settings,
atlas pixels/bank split, animation/mip/filtering state, lightmap pixels, time/weather,
GPU resources or device budgets. Callers must supply this context.

Production sprite arrays are split across up to eight banks (`gfx.rs:1568`);
device limits and a Metal-specific requested split influence the bank size.
G02 still has one array with a conservative 256-layer policy. A CPU export with
higher global layer IDs is preserved, NOT renumbered, and is not drawable by that
unchanged G02 policy. Atlas/bank support remains an integration blocker.
Production's lightmap is generated externally (`gfx.rs:7438`); `terrain.wgsl:301`
samples block/sky coordinates at texel centers. G02's synthetic lightmap is not a
replacement for this time/weather/gamma-dependent data.

## CPU contract and ownership

`src/section.rs` adds version 1, an in-process little-endian CPU contract, not a
portable serialized file or a new C ABI. It borrows expanded vertex bytes and
requires explicit format, 24-byte stride, vertex/quad counts and world-block origin.

| Field | Byte offset | Meaning |
|---|---:|---|
| position | 0 | `[f32;3]`, section-relative, fractional/offset positions preserved |
| UV | 12 | `[u16;2]`, 32768 steps per sprite unit; no tiled-LOD 32-step substitution |
| layer | 16 | `u16`, bit 15 opaque override, low 15 bits global sprite ID |
| light | 18 | `u16`, low byte sky and high byte block, 16 steps per level |
| color | 20 | `u32`, low-byte R then G/B, high byte emission/fluid metadata in normal shading |

Total stride 24, alignment 4. `TerrainVertex` is production `repr(C)`/Pod
(`mesher.rs:60`); `gfx.rs:29` binds corresponding GPU attributes. The typed adapter
asserts accessible field offsets/stride/alignment; tests also check literal UV
offset bytes even though the production UV field is private.

`prepare(input, limits, &mut index_scratch)` checks version/format, alignment,
counts/lengths, uint32 index range, arithmetic/allocation limits, finite positions,
available global layers, flat per-quad layer/flag and geometry/buffer budgets.
Malformed input is rejected before index writes or reservation. Empty sections
produce no draw (`Prepared::mesh()` is None), rather than an invalid G02 draw.
The CPU layer namespace permits the original 15-bit global IDs; it does not expand
Metal capabilities or bypass G02's own complete GPU resource preflight.

The result borrows both vertices and reusable caller-owned index storage. Rust
lifetimes prevent mutation/free while borrowed. `mesh()` reborrows a G02 `terrain::Mesh`
without any vertex conversion, quantization, sorting, dropped faces or CPU reference
image. `view()` subtracts camera from the separate integer world origin in f64 before
f32 conversion; column-major clip matrices and vertex bytes are preserved. Callers
still select matching reversed-Z clear/compare settings.

`tools/section_adapter.rs` accepts the ACTUAL production SectionMesh and borrows
`bytemuck::cast_slice(&source.solid)`. It is a production-side source module compiled
by the CPU test driver, not a dependency of the standalone Metal runtime. It can be
included by a future production-side utility; it is not wired into gameplay.
The driver resolves the real library artifacts from Cargo's JSON build output, so
no new dependency, package manifest or lockfile is introduced.

Packed sidecars are explicitly excluded and their slot count reported. Packed-only
meshes are rejected. Any nonempty translucent stream rejects the whole export,
avoiding an apparently complete section with missing translucent faces. Invalid
side-count metadata is rejected; zero/default side metadata is accepted, as in the
production upload fallback. All solid quads are included, without applying culling.
LOD, packed, translucent and shader-pack format tags are rejected. SectionMesh
does not itself prove provenance; the producer must attest normal baked-section
UV/material semantics. Raw bytes cannot establish that assertion independently.

## Memory and optimization assessment

For Q quads: 4Q vertices borrow **96Q bytes**, 6Q uint32 indices occupy **24Q bytes**,
and active geometry totals **120Q bytes**. For example, 4096 quads mean 384 KiB of
already-owned vertex data plus 96 KiB of indices. These are arithmetic sizes, not
benchmarks or device memory measurements.

Successful preparation allocates no vertex array and copies no vertex byte buffer.
Validation decodes temporary scalar values on the stack. Index scratch can allocate
once or grow; existing capacity is reused, but the pattern is rewritten per call.
Growth can copy prior index contents and temporarily retain old/new allocations.
Retained scratch capacity, source Vec capacities, allocator overhead, textures,
staging, GPU buffers and readback are outside this active-payload budget.
There is no automatic shrink or invented device-specific RAM allowance.

The existing G02 renderer still copies borrowed vertices/indices into new Metal
buffers per render, uploads textures and revalidates resources. The bridge does not
eliminate those copies. Keeping wgpu and Metal residency together could duplicate
GPU memory; no dual residency is introduced here.

Future investigations, not measured improvements or implemented optimizations:

1. Reuse a trusted universal GPU quad-index prefix sized to the largest section,
   with checked arena/base-vertex bounds, instead of per-section index buffers.
2. Validate once per mesh revision AND atlas/resource generation, invalidating on
   changes/device recreation. Reused Vec addresses are not revision identities.
3. Reuse buffers and batch uploads with explicit completion ownership. Benchmark
   equal source sections, bytes uploaded, allocations, peak residency and frame-time
   tails on A11/A15/A16 before claiming a benefit.

No GPU feature or iOS deployment setting changed; iOS stays 15.0. Actual A11/A15
compatibility and this bridge's Apple integration remain UNVERIFIED. Keep the
working production renderer as fallback. Next: review this CPU patch and obtain
an owner-prepared authentic mesh test result before any renderer integration.
