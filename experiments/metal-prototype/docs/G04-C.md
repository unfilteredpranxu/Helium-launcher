## Production data path and implementation

The renderer still builds `PreparedTextures`, selects its effective device split,
resplits production mip chains, captures only when opted in, and uploads unchanged
wgpu textures. `SpriteAnimator::new_observed` uses the **existing** `source_chains`:
production sheet mip generation, alpha/cutout strategy, native-size repetition and
frame word offsets. The GPU path uploads those frame buffers as before and moves
(not clones) their CPU Vecs into the observer only if its shared capacity budget
allows retention. The CPU fallback already owns its frame Vecs; refresh borrows
those buffers and creates no second copy.

`collect` still selects the frames, thousandths of interpolation, activity mask,
bank-local slice and changed global IDs exactly once. Before either writer clears
its groups, `refresh_observer` reads those actual encoded jobs. No second animation
clock, frame selector, simplified mip generator, or independent blend algorithm
exists. The fallback and refresh share `mixed_pixels`, the original integer
interpolation `(a*(1000-millis)+b*millis+500)/1000`. The fallback still appends to
its one mip Vec; refresh writes directly to preflighted layer ranges without a
temporary output Vec. WGSL and all existing reference oracles remain unchanged.

Refresh validates every job before any writes: bank and used-slice bounds (padding
is not a sprite), global identity, duplicate layers, power-of-two dimensions, source
frame offsets, complete source mip chains, interpolation range and checked byte
lengths. It regenerates **only changed layers**. Static layers and their ordering,
partial-bank padding, UV/geometry/lighting contracts and texture artwork are intact.
Malformed or missing input, memory rejection or workload exhaustion releases
observation and rejects subsequent consumption. Production animation still runs.
Recovery after rejection requires new capture through resource reconstruction;
there is no unsafe attempt to relabel a partial or stale snapshot as current.

## Immutable ownership and bounded allocation

Banks now share immutable `Arc<Payload>` buffers across snapshot revisions. If no
consumer pins the current revision, refresh mutates uniquely owned bank buffers in
place. With a pinned revision, it copies only the small bank-descriptor array and
banks actually changed. Unchanged banks share the same pixel allocation. A whole
changed-bank copy is necessary to retain the v1 contiguous-bank G04 interface;
per-layer overlays would require a different upload contract. It is never an
unconditional full-atlas copy. Several changed layers in one bank incur one COW
copy, not one copy per layer.

A shared atomic capacity ledger covers bank Vec capacities, snapshot bank-record
Vec capacities, retained GPU-source frame Vec capacities and their outer Vec.
Historical snapshots and temporary COW overlap remain charged until their last
owner drops, including on another thread. Charge reservation precedes new buffer
allocation; actual Vec capacity is accounted before copying. Allocation failure or
budget rejection cannot mutate a pinned buffer. No refresh history queue is kept.
Fixed owner/Arc/Payload/ledger headers, allocator bookkeeping and the original
production source/upload/GPU allocations are outside this **capacity** budget;
they are explicitly not reported as measured RAM. Header counts are bounded by the
charged snapshot/bank records; they cannot grow independently without limit.

`retain_material_snapshot(bytes)` remains the sole opt-in. Disabled capture has no
bank/frame retention, pixel copies, refresh heap allocations or frame locks.
Enabled GPU observation extends lifetime of already generated frame buffers; it
never generates them again. Source buffers already used by the CPU fallback remain
ordinary production memory, not extra observation residency. No GPU readback is
introduced into gameplay.

The default refresh write limit equals the configured capacity budget.
`Renderer::set_material_refresh_limit(bytes)` can lower the allowed regenerated
bytes per update. This limits **writes**, while bank COW copies are separately
bounded by the shared capacity budget. Exceeding either rejects observation; it
does not defer/disable production animation or expose stale data.

For square edge S and L levels, each layer occupies
`C = sum(4 * (S >> level)^2)`. K changed layers regenerate K*C bytes. With unique
banks the additional heap allocation and pixel-copy count are zero. With pinned
banks the extra allocation is the new descriptor capacity plus the capacities of
changed banks; old and new remain simultaneously charged. Static bank bytes are
not copied. Existing constructor/resplit scratch and upload staging are unchanged.
The refresh preflight uses fixed stack bitsets (4096 bytes for duplicate detection)
and scalar state, with no retained scratch or per-mip refresh Vec.

`State::counters` reports actual software-operation counts: updated layers,
regenerated bytes, initialization/COW copied bytes, cumulative uniquely reused bank
capacity, superseded revisions, invalidation events, failed refreshes/budget checks,
live/peak charged capacity, retained source-frame capacity and maximum newly
allocated COW capacity in one update (`temporary_peak_capacity`). These are not
GPU timings, allocator RSS, jetsam limits or performance benchmarks. Invalidations
count transitions from usable observation to unavailable; generation values are
identities, not a count of previous renderers.

## Revisions, authorization and synchronization

Each snapshot carries its production generation and animation revision. The
producer's `current` and `check_ticket` reject superseded revisions as well as
obsolete generations. Revocation remains effective after release, budget failure,
pack reload or renderer/device reconstruction; no pointer/frame-number identity is
used. A retained old snapshot remains immutable historical data, never authority
for a new upload. A borrowed validated view prevents mutation of its owner.

`Phase` distinguishes initial CPU content, encoded target content,
queued-for-submission, submitted-unconfirmed, released and unavailable states.
The main synchronous submit marks submitted; successful deferred handoff marks
queued. The deferred worker's actual submit/completion is intentionally not
inferred. CPU reconstruction happens before encode returns, so consuming it means
consuming the intended bytes of that revision, **not completed GPU output**.

There is no GPU completion proof in this boundary. `gpu_current` always rejects,
including initial content and submitted-unconfirmed content. There is no public
"mark complete" escape hatch. A future hook must associate an exact queue
submission/completion with the generation/revision and retain owners through it;
queue handoff, elapsed time and successful Rust compilation are insufficient.

The typed adapter's binding extension is explicitly `BINDING_VERSION = 2`.
G04 material contract v1 is preserved. `Binding::consume` is scoped CPU-target
consumption and now takes `&mut self` so a successful revision change invalidates
its experimental epoch. It checks current production generation/revision,
lightmap readiness/revision, supported mode and G04 validation. Bank descriptors
stay on the stack; no texels are copied. HDR, PBR and shader-pack rejection remains.
G02 single-array GPU capability checks and G03 geometry/provenance checks remain
unchanged. CPU validation never grants Metal multi-bank drawing support.

## Validation and authenticity

Fixtures are handcrafted and use real production source chains, collected jobs,
mip generation and fallback mixing. Refresh tests exercise global sprites
257/258/512, multiple animations per bank, cross-bank changes, a partial final
bank, interpolation boundaries 0/1/499/500/501/999/1000, frame transitions,
inactive/unchanged frames, alpha/cutout data, all mips, immutable historical owners,
unique-bank reuse, budgets, corrupted/missing/duplicate jobs and cross-thread drops.
Existing independent integer/reference and production mip tests are retained.

The opt-in `observed_snapshots_match_gpu_animation_jobs_every_tick` test requires
an actual compute adapter; it fails rather than silently returning when unavailable.
It constructs the real GPU writer with retained frame buffers, runs real animation
compute jobs and compares readback to refreshed snapshot mip bytes and the existing
independent reference across the tick sequence. This readback is test-only.

On this Linux host the explicit Vulkan attempt failed before execution: a Vulkan
loader exists, but no installed ICD/adapter. The separate OpenGL run passed on
`llvmpipe (LLVM 19.1.7, 256 bits)`, device type CPU, Mesa
`4.5 (Core Profile) Mesa 25.0.7-2+deb13u1`. This is **software OpenGL compute parity**,
not Apple GPU, Vulkan, native Metal or physical-device evidence. The original GPU
checks can return early without an adapter; they are not relied upon as GPU proof.
Two existing asset-dependent animation tests also return early without their
Minecraft files; their runner "ok" status does not establish authentic-resource
coverage. The authentic G03 resource test remains ignored.

Prepared Minecraft resources were not present, downloaded or fabricated. To run
the authentic G03 case, use the adapter driver's `--resources` option with the
owner's prepared `horizon-client/26.3` directory. The asset-dependent animation
checks need textures under `.local/horizon-client/26.3/assets/minecraft/`.
No proprietary files are added.

No performance, FPS, thermal, physical peak-memory or Apple GPU measurements were
made. Existing iOS deployment minimum, shaders, gameplay, saves, launcher UI,
dependencies and lockfiles are unchanged. No IPA or app packaging was run.
