## Source investigation

`Sprites::finish` produces square RGBA base images, global names/IDs, opacity,
translucency and per-layer `mipmap::Settings`. Names can alias a sprite; the name
count is not the layer count. `gfx::mip_chain` uses the production generator
(alpha coverage/linear-light averaging), storing each layer's mip chain contiguously.
`PreparedTextures::resplit` adapts these chains to the actual device split.
`gfx::layer_split` caps at 2048, eight banks, with a Metal default request of 512;
OpenGL may add padding layers. Padding has no global material identity.
`terrain.wgsl::sprite_grad/sprite_level` select the array by global ID divided by
SPRITE_SPLIT and the slice by its remainder. G04 uses checked range validation
before the equivalent partition; it never wraps a missing ID into a valid material.

`gfx::update_lightmap` generates 16x16 RGBA8Unorm: index `(sky*16+block)*4`.
Sky parameters, flicker, darkness, night vision, boss darkening, gamma and fullbright
participate. Identical pixels avoid a repeat upload. `gfx/upload.rs::Uploads`
uses staging with finish/recall ownership. WGSL samples light linearly at clamped
texel centers, with low vertex byte sky and high byte block (16 steps/level).
G04 borrows these actual bytes via `Renderer::lightmap_pixels`; it does not reimplement
lighting or use G02's synthetic lightmap. An uninitialized zero-alpha image fails.

Resource-pack reload swaps the streamer's `Arc<WorkerContext>`; mesh jobs retain
that context. This is NOT a generation identifier exposed to this experiment.
Animations update renderer mip data after initial resource loading. Consequently
`Sprites::pixels` must not be passed off as the current animated GPU atlas.

## Version 1 boundary

`material::Resources::new` validates borrowed layer-major bank chains, the required
mip count, uniform square power-of-two dimensions, linear RGBA8 format, used versus
allocated layers, exact byte lengths, device-policy limits and payload budget.
Global IDs are preserved through 32767, subject to the production eight-bank limit.
`Resources::sprite` accepts an ID, not a vertex's opaque flag; G03 already masks
that flag only for validation and preserves the original vertex word unchanged.
`validate_section` binds a G03 prepared section to an epoch and namespace.
No vertex, index, shader or G02 GPU preflight code changes.

`material_adapter::source` borrows actual `Sprites` fields including original
mipmap settings and the complete name map. It validates counts, IDs, base payload
and finite settings, and rejects PBR. This is a base-source description, not an
upload-complete bank snapshot. The typed lightmap helper borrows the renderer's
last generated image, labels its provenance, and accepts an owner-supplied revision.
The existing adapter harness compiles both adapters against the locked production
and experimental graphs.

Epochs are unique within the process, checked for exhaustion, and never recycled.
Snapshots borrow an epoch and their pixels; Rust prohibits mutating/dropping these
owners during consumption. Cached tickets must be checked against the current
snapshot. Invalidate on pack reload, bank regeneration, animation atlas update or
device recreation; lightmap tickets additionally check their dynamic revision.
There is no claim that these notifications are wired into live production yet.
The integration owner must issue stamps when capturing resources, not retrospectively
relabel stale bytes. Provenance is explicit caller attestation, not byte inference.

Translucent, packed-only, tiled-LOD and shader-pack section sources retain G03's
rejections. Material descriptors reject non-baked provenance and HDR/PBR requirements.
Per-sprite translucency metadata can be inspected but does not authorize a translucent
mesh export. Required mip levels cannot be fabricated. Sampling/filtering parity,
HDR emission thresholds and PBR are not implemented by the G02 renderer.

## Memory and remaining integration boundary

Success allocates no pixel, metadata or geometry buffers. Bank descriptors and texels
are borrowed; validation uses scalar stack state. Payload accounting includes bank
padding/mips and the 1024-byte lightmap, using checked arithmetic and Rust allocation
bounds. It excludes producer Vec capacity, allocator overhead, GPU layout/staging,
and G03 retained index scratch capacity; no GPU residency is created. G03 still
accounts active geometry separately. There are no G04 retained scratch allocations.

Production prepared mip chains are private and consumed at GPU construction. A
future producer-side capture point must expose the exact post-resplit chains and
animation updates, attach epochs to streamed meshes, and advance light revisions.
That requires a deliberate production lifecycle integration; this patch does not
pretend that manually supplied descriptors implement it. Until then G04 is PARTIAL
against the full milestone acceptance criteria, though its CPU validation is usable.

Next dependency: implement and validate that producer-side snapshot/lifecycle hook
with authentic owner-prepared resources, before adding any Metal bank upload path.
Future batching/residency should retain completion-protected snapshots, with bounded
queues. No performance, GPU timing, FPS, thermal or memory-peak measurements were made.
iOS 15 remains unchanged. Rust target checks are not Apple SDK compilation or GPU execution.
