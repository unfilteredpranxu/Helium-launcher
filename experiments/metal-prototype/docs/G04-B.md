## Implemented path

`PreparedTextures::retain_material_snapshot(budget)` opts into observation; zero
(the default) disables retention. The production renderer calls `capture_materials`
**after** its actual `resplit(layers, split)` and before consuming the original
chains for GPU upload. Capture copies those chains, not `Sprites::pixels`, and
never invokes another mip generator. Captured dimensions/count must match the
original prepared source. The explicit format is RGBA8Unorm. Banks preserve the
runtime split (including Metal's existing default request of 512), up to eight
banks, used/allocated layers, complete mip counts, and layer-major then mip-major
byte order. Padding matches `array_layers` and the production zero fill. No global
sprite IDs are renumbered. Failed observation leaves the production upload intact.

The narrow public capture method can also inspect a prospective prepared layout
without a GPU; that observation is NOT an authorization for a device. Only the
state stored by the actual renderer carries its current generation. The G04
`Binding` always checks that state; a prospective capture has a different identity.

`Binding::consume` connects the real renderer-owned snapshot, real generated
lightmap and revision to G04-A's `Resources::new`. Eight bank descriptors use stack
storage; pixels are borrowed. Its callback cannot return a borrowed Resources view
past the owner. G04-A v1 remains unchanged; this is an additive authoritative
producer binding. The old low-level lightmap helper remains for compatibility;
new integration uses the producer's revision, not a caller-invented frame number.
HDR, PBR, active/loading shader packs are rejected. G03 geometry/provenance guards
and G02's single-array/256-layer GPU policy remain authoritative and unchanged.

## Lifecycle and threading

Each actual renderer gets a new, process-local generation from a checked monotonic
atomic counter. IDs are not pointers, ticks or serialized cross-process identities.
Counter exhaustion fails closed instead of reusing an identity.

`game/packs.rs::apply_pack_reload` builds a new renderer before switching over.
Successful reload therefore changes generation; failed reload preserves the old
renderer and its valid resources. Device recreation through renderer construction
also changes generation. Surface recreation alone does not replace atlas resources.
`Streaming::reload_resources` replaces the Arc worker context and clears pending
mesh sequence entries; completion rejects results whose sequence is no longer
current. Those existing ownership and rejection mechanisms are unchanged. The new
code neither relabels old meshes nor rewrites streaming.

`SpriteAnimator::collect` clears and repopulates its existing changed-global-ID
list, skipping unchanged or inactive sprites. Both its compute writer and CPU
fallback consume those same jobs. Immediately after `animate` encodes the writes,
the renderer increments the animation revision for a nonempty changed list and
invalidates/releases its CPU atlas snapshot. `changed_material_layers` exposes the
actual IDs without copying. Invalidation is conservative for the whole snapshot,
even if only one bank changed. It does not wait for GPU completion, silently retain
stale pixels, disable animations or read textures back. A submitted update that
later fails is still treated as invalid; stale CPU data is never reinstated.

Refreshing animated snapshots is intentionally unsupported in this milestone.
Consumers receive an explicit refresh-required error. The acceptance path is
reliable invalidation, not a claim of complete CPU animation pixels.

`update_lightmap` remains the sole production generator. Its unchanged pixels are
not assigned a new revision. The first generated image becomes revision 1;
subsequent different images advance it. The source remains the exact 1024-byte
RGBA image indexed `(sky * 16 + block) * 4`. A zero/uninitialized state is rejected.
No lighting formula, texel placement or shader sampling changed.

State mutation requires exclusive renderer access. A `current` view borrows both
state and bytes, preventing concurrent invalidation through safe Rust. Retained
`Arc<Snapshot>` handles are explicitly historical: callers must validate them
against the current owner before reuse. They can retain old immutable bytes for
in-flight upload completion after renderer destruction, but cannot make those
bytes current on a new renderer. No locks were added to the frame path.

## Memory accounting

Disabled: no captured pixels, bank Vec or Arc; only fixed scalar lifecycle state
and generation allocation once per renderer. No extra GPU residency.

Enabled: one copy at construction of each existing production bank. Budget checks
cover bank-record capacity plus actual retained pixel Vec capacities, including
padding. Each layer's bytes are `sum(4 * (size >> mip)^2)` for all levels. Counts,
lengths and products are checked before allocation. Metadata is capped at eight
banks. Small fixed State/Snapshot/Arc headers and allocator bookkeeping are outside
the payload budget. Peak construction also includes the existing original chains,
resplit scratch and normal GPU upload data; capture does not hide those costs.

No per-frame copy or refresh allocation. Release, first animation mutation or
renderer destruction drops the renderer's Arc. External upload owners may retain
historical handles until completion; their aggregate budgets/completion tracking
remain the future uploader's responsibility. Cloning an Arc does not copy pixels.
This patch creates no new GPU upload queues or GPU ownership.

## Validation scope and authenticity

Tests use handcrafted inputs through actual `PreparedTextures::with_split`,
`mip_chain`, `resplit`, `layer_split`, and the same capture function called by
Renderer::new. They compare captured bytes to the production-prepared chain,
including partial banks and OpenGL padding, rather than implementing another mip
oracle. The adapter regression passes production-generated mip bytes through G04
and explicitly labels its lightmap SyntheticFixture. A separate deterministic
animation test uses the actual collect/job encoding at global sprite 257 without
requiring a GPU. Lifecycle tests cover revision changes, invalidation, retained
ownership, generation replacement, malformed metadata, mip corruption and budgets.

These are authentic production code paths operating on handcrafted fixtures, not
Minecraft-resource or hardware evidence. The pre-existing authentic section test
requires `--resources /path/to/owner-prepared/horizon-client/26.3` on the adapter
driver. No proprietary assets were downloaded or committed.

Apple SDK/Metal compilation and GPU execution were not run. The host is Linux;
`xcrun` is unavailable. Existing Apple CI targets the old prototype branch and
builds an app; it was not repurposed or triggered. No IPA, shader changes, live
Metal backend, deployment-target change or dependency upgrade was made.

Performance, FPS, thermal behavior and peak memory were not measured. Memory
figures above are analytical allocation accounting only.

Next implementation dependency: a bounded animated-snapshot refresh path using
production animation jobs, validated against production GPU output before any
multi-bank Metal rendering integration. Do not infer that G02 can draw these banks.
