## C — Display architecture

A G05-C completion receipt is consumed exactly once into CompletedFrame. Its
private presentation lease checks current source/device/material authorization,
borrows the frame/material/producer and retains the color texture without exposing
raw texture pointers. A worker-owned Display retains a genuine CAMetalLayer and
requires same device, BGRA8Unorm, explicit named linear-sRGB, integer nonzero
physical dimensions, conservative 4096-side policy and timeout-enabled acquisition.

Display is deliberately one-shot: one accepted frame per display generation. A
fresh view/layer request represents resize/recreation; no historical drawable pool
or general frame scheduler exists. The conversion pipeline is immutable for that
display lifetime, not rebuilt inside submission/poll. This diagnostic host draws
once per lifecycle/layout request rather than providing continuous display pacing.

`nextDrawable()` is one acquisition attempt on a dedicated worker, with
allowsNextDrawableTimeout=true. It MAY BLOCK for Apple's drawable timeout; this is
not a zero-wait acquisition API. Main-thread entry rejects before acquisition.
No drawable is explicit Unavailable. Zero sizes/background/disappearance cancel;
resize replaces the child layer instead of racing its configuration with encoding.
The worker rechecks cancellation/size after acquisition. GPU command submission
and individual polling never wait/sleep/spin. The separate diagnostic worker driver
uses 2ms sleeps between observations; it is not a gameplay frame synchronization
strategy. A hung GPU may keep that one worker/permit retained indefinitely, without
stalling UIKit or admitting an unbounded queue.

## D — Color, orientation and fidelity

The existing source is RGBA8Unorm; CAMetalLayer uses legal BGRA8Unorm, not an
assumed RGBA drawable. The GPU render pass samples semantic RGBA and lets the
BGRA attachment encode channel storage. No CPU swizzle/image exists on the normal
path. Point/clamp sampling preserves original bytes at equal size and avoids
interpolation; viewport aspect-fit preserves the image ratio with black bars.
Triangle UVs explicitly map top-left source row to top-left output row. Alpha
is passed through; the G02 solid oracle image itself is opaque. The layer uses
linear-sRGB, matching the source's established interpretation. Core Animation may
perform ordinary display color management; no display-code-value identity or
physical colorimetric result is claimed.

The diagnostic GPU conversion test uses actual RGBA source pixels:
red/alpha17, green/alpha127, blue/alpha128, white/alpha255, at four distinct corners.
It reads back the actual BGRA target and asserts all 16 bytes exactly, detecting
channel swaps, orientation reversal, alpha loss and unwanted shader gamma changes.
This is a separate conversion test, not a replacement for the unchanged independent
G02 full-image oracle. G05-C still runs its original whole-image comparisons.

## E — Ownership and ABI

Presentation holds its completed-frame borrow, exact retaining command, drawable,
and owned CPU/native cleanup lease. This prevents reuse/release of the borrowed
frame/material until the presentation owner drops. The copied completion block
captures only Arc-owned CPU source/permit and binding-declared Send+Sync device/
queue references, not commands, drawables, layers, Swift views or mutable sessions.
No strong command callback cycle, unsafe Send/Sync, self-referential structure or
borrowed callback memory is introduced. Metal's retaining command owns its encoded
native resources after Rust owner drop; the copied lease retains source/permit
until terminal cleanup. The pending owner also holds the lease until observation,
matching G05-B/C's conservative outstanding-operation policy. No destructor waits.

FFI handles are monotonic u64 values, never addresses. The mutex registry admits
one request; handle claim and release are serialized under its lock. Stale/null/
wrong-class inputs reject (arbitrary dangling C pointers remain caller-invalid).
Swift owns the live layer throughout run, Rust retains it synchronously. Run is
single-use and worker-only; status/cancel/release use atomic token state without
moving non-Send Metal objects between Rust threads. Repeated release is harmless.
Rust unwind panics are caught in run; Objective-C exceptions/process aborts are
not recoverable by this ABI. Cancellation revokes authority, not GPU execution.

## F — Completion and invalidation

Frame completed -> drawable acquired -> conversion encoded -> presentDrawable
scheduled -> command committed -> actual terminal observation. Only that command's
Completed AND no NSError AND current source/device/layer state produces success.
Nonterminal revocation remains pending; terminal failure cannot become success.
Progress rejects repeat receipt observation and a second submission. Wrong device,
changed source authority, layer size/colorspace changes and cancellation reject.
GPU completion proves execution of presentation work, NEVER scanout or user visibility.

Review repaired: source texture ShaderRead usage; retain the pending cleanup lease
in both owner and completion block; serialize handle claim with release; validate
named colorspace and reject changes; preserve layer ownership across disappearance.

## G — iOS integration

The existing SwiftUI probe now embeds a UIKit DisplayView with an actual Metal
layer. Layout computes physical pixels from the view's window-screen scale; aspect
fit is encoded on GPU. The main thread creates/removes layers and updates labels.
A dedicated Thread performs all Rust/Metal session work, so dispatch queue thread
migration cannot violate ownership. Timers read atomic status only. Background,
dismantle and disappearance cancel and remove the layer; foreground/layout starts
a new generation when the bounded registry is available. No UIImage substitutes
for the native surface. Existing G01/G02 image/report UI remains available.

## H — Memory and counters

Explicit 64MiB diagnostic policy, not an application RAM entitlement. Checked
preflight charges current completed-frame payload plus **three** possible BGRA
Core Animation surfaces (12 bytes per drawable pixel), conservatively bounding
pool residency rather than counting only the acquired drawable. No source atlas
reupload or CPU image is needed for presentation. Conversion uses vertex_id and
no additional vertex/uniform buffer. Metal/CA allocation rounding, pipeline,
command/driver metadata and physical RSS are unmeasured and excluded.

Display counters track submissions, completions/failures, unavailable acquisition,
busy/skipped requests, polls, invalidations, resize invalidation, one recreation
per new Display and current/peak accounted payload. Diagnostic readback counter
stays zero on the normal path; the standalone conversion test reads 16 pixel bytes.
Counters describe component payload/events, not process RAM or display FPS. A
256x256 drawable's three-surface reservation is analytically 786432 bytes in
addition to the completed frame's retained accounting. Resize overlap retains at
most the cancelled old layer/session while the one-request registry defers its
replacement; repeated UI retry does not queue GPU work.
