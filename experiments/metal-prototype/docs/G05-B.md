## Implementation

`Material::begin_upload` uses the SAME immutable G05-A Plan, Source authority,
pitches, initialized staging and persistent texture. It validates, encodes and
commits; it never calls a wait, sleeps, spins or creates a pipeline. It returns
submission only, not a receipt. CPU preparation/allocation is still synchronous
and bounded, so this does not claim zero CPU latency or a measured frame budget.

`poll_upload` performs one owner-thread observation of the exact command buffer.
It returns Idle, Pending, Completed(receipt), or Failed(reason). A tiny command
may already be complete on the first poll. Repeated polling cannot reissue a
receipt: terminal observation consumes the pending slot. Actual `Completed` status
AND no NSError AND current producer authority are required for success. Error
status, revoked source/revision, release or wrong native device-owner nonce cannot
produce a receipt. Nonterminal NSError/revocation is not a safe destruction signal;
resources stay retained until actual Metal Completed/Error terminal status.

One process-wide atomic permit bounds upload work/retirement even across renderer
recreation and dropped materials. Busy submission rejects before staging or command
allocation. The original blocking API also honors that permit, preserving its
explicit wait semantics without overlapping a new nonblocking upload. Device
nonces still isolate resource ownership. No production wgpu rendering is changed.

Pending state blocks another upload, resident drawing, readback and receipt use.
Partial updates retain G05-A's complete-layer/full-mip semantics and comparison of
omitted bytes. Failed/revoked partial work clears completed source residency; a
verified full upload is required for recovery. Texture creation rejects while the
process upload/retirement slot is busy; no hidden replacement of in-flight storage.
The existing 4096-side/256-slice policy and sprite mapping are unchanged.

## State transitions

- Idle means no Pending object (the existing resource can be Prepared, Completed,
  Failed or Invalidated). Preparation validates the current immutable source.
- Prepared → Encoded after the checked blit encoder ends.
- Encoded → Submitted only after this actual command is committed; Pending owns
  all required state BEFORE commit, so even an unexpected protocol error retains it.
- Submitted/Pending → Pending when a poll sees nonterminal actual Metal status.
- Submitted/Pending → Completed only on this command's real successful terminal
  status with current source/device authority. This creates one G05-A receipt.
- Failure or source/release invalidation revokes residency; terminal observation
  releases the pending owner and returns failure, never success for a newer revision.
- Release while pending changes authority immediately but does NOT cancel the
  command or pretend completion. Released material cannot be resurrected.

An old completion cannot update a different owner: the callback never mutates any
record, and polling checks the private operation/device/material nonces and actual
source generation/revision. G04's global `gpu_current()` remains unchanged. A bank
receipt is not whole-renderer synchronization.

## Safe nonblocking destruction

objc2-metal does NOT mark the command buffer or texture protocols Send. They are
not moved to a Rust cleanup thread and no unsafe Send/Sync implementation is added.
Owner-thread polling handles completion/receipts. A minimal Metal completion block
is used ONLY as an owned CPU keepalive, to make release/drop safe without waiting.

The new async API requires `S: Source + Send + Sync + 'static`. The production
BankSource is an immutable Arc-backed CPU snapshot and satisfies this constraint;
its borrowed Renderer authority is never captured. The completion closure captures
an Arc containing new/historical CPU source owners, the permit, and device/queue
refs whose protocols ARE explicitly Send+Sync in the bindings. A generic assertion
checks the entire capture is Send+Sync+'static. It captures no command, texture,
staging buffer, borrowed stack reference, or self pointer. Its command argument is
unused; it makes no success assertion and dereferences no native pointer.

`queue.commandBuffer()` is the documented RETAINING command-buffer API. Metal
retains texture/staging resources through execution. Rust Pending also owns their
Retained handles, the exact command, descriptor and keepalive. `addCompletedHandler`
copies the owned block. Dropping/releasing Material drops Rust handles WITHOUT
waiting; the copied completion lease keeps CPU owners/permit alive, and Metal keeps
GPU resources alive until its terminal event. There is no self-referential
command/callback cycle or worker-thread transfer of non-Send Metal objects.

The permit releases only after the last pending/completion lease disappears.
Consequently a Completed poll can precede final callback disposal briefly: a new
begin may still return Busy during terminal cleanup. Retry on a later owner tick;
do not spin in a gameplay frame. A GPU that never reports a terminal event keeps
one bounded lease reserved; timeout is never treated as completion, and no growing
retirement queue is permitted.

## Dependency necessity

Apple's addCompletedHandler binding is gated by objc2-metal's `block2` feature.
The experiment adds exactly pinned `block2 = 0.6.2`, already present in the root
repository's dependency graph, and enables that existing Metal binding feature.
No existing version is upgraded. The experimental lockfile adds that package and
its existing objc2 dependency edge only. This avoids handwritten Objective-C block
ABIs, borrowed callbacks, unsafe thread coercions or blocking destructors.

## Memory and counters

G05-A preflight still budgets GPU mip payload, CPU staging Vec, Metal staging copy,
copy metadata and both retained source payloads. Source bytes are not recopied
except into the required staging upload. After native buffer creation the temporary
CPU staging Vec and plan metadata can drop; Pending retains the native staging
buffer, persistent texture and source owners through completion. Arc wrappers add
bounded fixed headers, not pixel copies. Existing capacity budgets exclude fixed
headers, allocator bookkeeping and driver padding, as documented in G05-A.

Counters include submitted/completed/failed operations, invalidations, committed
upload bytes, pending count/polls, live and peak staging/source capacities, texture
payload, resource reuse and rejected budgets. Busy is not a failed GPU command.
`TerrainRenderer::upload_retention` reports process-slot gauges even after a Material
is released/dropped; gauges are diagnostic atomic observations, not a transactional
cross-thread RSS snapshot. Their source values conservatively include historical
owners and can overlap Material's current source retention; do not add them as
independent physical allocations. Fixed slot metadata does not grow with frames.

The standard production renderer and disabled experiment gain no runtime work.
There is no blocking destructor, GPU readback in update/poll, shader rebuild,
unbounded command queue, spin loop or frame-path mutex. The old render/readback
APIs remain explicitly blocking diagnostic operations and reject pending residency.

## Owner verdict

**PASS for G05-B's bounded single-bank nonblocking upload implementation.** All 11
implementation criteria have passing code/test paths: no GPU wait in begin/poll,
owned pending state, one permit, actual status/error completion, receipt identity,
source/GPU retention, safe release/drop and full repair, generation rejection,
persistent reuse, CPU/native regressions and published continuation history.

This is not a physical iPad qualification or a nonblocking draw/gameplay backend.
The original render/readback/blocking-upload methods remain explicit diagnostic
waits. The completion callback is only cleanup ownership, never authority or a
substitute for actual GPU status. The final report-recording commit changes this
document only; code and workflow are identical to the validated commit above.
