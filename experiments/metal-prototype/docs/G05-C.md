## Implemented boundary

`frame` v1 extends the existing G02 TerrainRenderer and G05 Material, without
changing the production wgpu renderer. `create_frames`, `Frames::begin`, `poll`,
`take_completed` and `release` provide an owner-thread, one-slot native draw path.
`CompletedFrame` borrows verified output and its controller/material/producer;
it cannot outlive those owners or allow target reuse while borrowed. No raw
texture escapes to an untracked external command. Presentation is future work.

The private reusable residency stamp identifies the exact completed upload,
source generation/revision, material owner and device nonce. It is derived only
from a Completed upload record, not a public flag or repeatedly consumed upload
ticket. `Material::resident` checks live producer authority, metadata, device,
texture ownership, pending status and bank zero. Every begin/poll/output access
checks authority; a newer write invalidates the old stamp. Nonzero banks reject
because the existing G02 shader uses global sprite IDs without remapping. The
4096-side/256-slice limits remain unchanged; no full-atlas claim is made.

Both old blocking diagnostics and new nonblocking drawing call the SAME extracted
`encode_terrain` function: same pipeline, shaders, geometry bytes, uniforms, point
sampling, lightmap, alpha/cutout, indexed topology and depth states. G03 geometry,
G04 semantics and all image oracle thresholds remain unchanged. New frames copy
borrowed vertex/index bytes into owned Metal buffers before GPU access. Only the
16x16 lightmap is staged; the resident material is neither copied nor reuploaded.

## Synchronization and lifetime

Prepared -> Encoded after the shared render encoder ends; Submitted only after
actual commit. Pending owns all native resources BEFORE commit. Submission and
poll perform no wait, sleep or loop and never allocate a CPU readback buffer.
CPU validation, allocation and encoding still take time; no latency claim is made.

One process-wide atomic permit serializes native uploads, draws and their terminal
cleanup. Busy returns an error without waiting. Conflicting uploads, diagnostic
resident rendering and material readback reject while a frame is pending. At most
one submitted upload/draw can retain resources, including after its Rust owner is
dropped. This deliberately conservative policy is not a multi-frame scheduler.

Poll examines the exact retaining command buffer. Only actual Completed AND no
NSError AND current source/device/material authority can issue a one-use frame
receipt. Error, stale revision/generation, release, wrong device or supersession
fail closed. Invalidated work stays Pending until native Completed/Error; logical
cancellation does not retire GPU resources. Poll after terminal returns Idle.
Older frame receipts cannot authorize a new operation or be consumed twice.

Pending Rust ownership retains mesh/index/uniform/staging buffers, lightmap,
material texture, pipeline/depth state, command and color/depth targets. The
retaining Metal command buffer also owns all encoded native resources. Its copied
completion block captures ONLY an owned CPU source/permit and binding-declared
thread-safe device/queue references. The capture is compiler-checked Send+Sync+
'static, has no command reference cycle, borrowed state or unsafe Send/Sync impl.
It never publishes status. Drop/release perform no GPU wait; orphan work retains
its bounded ownership until actual terminal cleanup. A hung command keeps the
single permit busy rather than releasing memory unsafely or queueing more work.

## Memory and diagnostic output

One reusable private RGBA8 color/Depth32Float target pair is retained per frame
controller; same-size draws reuse it only after retirement. Other frame buffers
are allocated per submission; buffer-pool reuse is not implemented or claimed.
Changed dimensions discard the old completed target before new allocation. There
is no history or externally cloned output. Normal payload preflight counts source
capacity, resident mip payload, vertex/index bytes, 80-byte uniforms, 1024-byte
lightmap, 8 bytes/target pixel and two 4096-byte staging payloads (stack + Metal).
Peak accounting includes the stack staging; retained accounting removes it after
submission. Metal allocator rounding, command/driver/pipeline overhead and process
RSS are not measured or included in these deterministic payload counters.

`Counters` records submitted/pending/completed/failed/invalidated frames, busy
rejections, polls, current/peak payload, reused targets and diagnostic readback
bytes. The shared retention gauges separate material texture, staging, source and
other frame GPU payload. They are diagnostic atomics, not a transactional memory
snapshot. Counters are saturating diagnostics, never completion authority.

Explicit `CompletedFrame::readback_for_validation` is a blocking diagnostic worker
operation after genuine draw completion and receipt consumption. It acquires the
same permit, validates a separate budget for retained payload + shared readback +
tight CPU image, checks status/error, and reads initialized row prefixes only.
It is never invoked by normal frame submission/poll. No readback per frame is
required. No display surface/gameplay integration, IPA or proprietary assets.
