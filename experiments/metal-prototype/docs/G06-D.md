## D — Event schema and ABI

Schema **2**, stable numeric stage/cause/emitter codes, boot ID, unique attempt ID,
world epoch, serialized sequence, Rust monotonic nanoseconds, per-attempt elapsed
milliseconds, first-cause flag, expected/observed numbers, last confirmed stage,
possible GPU-in-flight flag and TEST_ONLY provenance. One mutex serializes both
Rust and Swift callback events using one Rust clock. This orders observed events;
it does not invent an earlier unobserved OS/material transition.

All worker/Flight/Shown/Ticket events carry explicit attempt identity. Context
checkpoints use ID 0 and never silently become the latest attempt. Admission
rejects duplicate/zero/fourth IDs; busy native admission cannot reset an existing
first cause. Reserved first-cause records and terminal retry-stop history survive
timeline eviction. Historical events cannot rewrite current HUD state.

Early isolated initialization runs in `entry.rs` immediately after sandbox selection, before resource import/window creation. It does not attach UIKit or allocate GPU resources. Mode selection also records the packaged build number in the report header.

The five `horizon_native_display_*` **ABI v1** signatures and version remain
unchanged. Additive **v2**:

- `horizon_diag_install_v2(u32, event_fn, snapshot_fn) -> u32`, returns 2 only in the qualified isolated bundle;
- event callback `(u64 attempt, u32 stage, u32 cause, u64 expected, u64 observed) -> u32`;
- snapshot callback copies exactly 32 caller-owned u64 words synchronously;
- `horizon_diag_hud_v2` synchronously borrows the actual live winit UIView;
- `horizon_diag_host_idle_v2` queries main-owned host admission without waiting;
- Rust `helium_diag_*_v2` exports provide the typed recorder/snapshot and host-only
  synthetic admission/flush harness. Test admission and blocking test flush reject
  on iOS. Unknown codes/stages reject. Swift cannot emit GPU-completion stages.

No temporary Swift strings or borrowed buffers escape. On iOS UI_REVEALED
recording also requires the private native completion/publication gate; a status
callback cannot forge that proof. A real bank completion still does not change
G04 `gpu_current()`.

## E — Independent HUD and host lifecycle

`MetalDiagnostics.swift` adds a noninteractive UILabel **sibling** on the actual
winit parent, outside the alpha-zero `NativeMetalView`. It remains after that
child is removed, indefinitely while the game parent remains alive (exceeding 60
seconds); a new parent replaces it. It has no touch interception or new UIWindow.
Safe-area constraints place it left/middle, away from the top-right performance
HUD and bottom movement controls. The launcher modal hides the label while
recording continues; it reappears when the modal closes. A 5 Hz main-thread timer
changes text only when the snapshot changes. Reattaching the native child lifts
the independent label above it. Physical UIKit layout/input remain device tests.

HUD: G06-D test identity, AUTO/CONFIG/OFF/INVALID mode, attempt/stage/elapsed,
bank progress, generation/material/light revisions, typed first cause, possible
pending GPU work, historical native reveal flag, recorder ack/loss/degradation,
preflight and exact Files path. It never says Metal PASS or infers scanout. No
optional HUD toggle or Share Sheet shipped: the minimum automatic Files export

The actual existing winit UIView is not MTKView. wgpu's Metal surface and the

## G–H — Persistent storage, durability and export

One background writer snapshots a bounded 256-event ring plus three reserved
first causes. Producers perform bounded mutex/state work, not disk I/O or JSON
formatting. Every 200 ms the writer atomically replaces initialized JSONL and the
plain report; acknowledgement advances **only after both writes/renames succeed**.
Priority is in reserved memory, not a saturating channel which can drop the cause.

`Documents/logs/Helium-Metal-Report.txt` is created automatically at diagnostic
startup and updated after failure, success, cancellation, retirement and retries.
The report contains human millisecond chronology, per-attempt first causes,
previous-boot causes, source/layout/upload metadata, last acknowledged sequence,
loss/write-error counters, normalized timeline, next action and
PHYSICAL_PIXELS_UNVERIFIED. JSONL is beside it. A malformed tail is counted, never
copied verbatim. Repeated boots with no new attempt preserve the prior failure;
previous incomplete work is distinguished from genuinely acknowledged retirement.
No claim is made about why an OS process ended without a terminal record.

Limits: active/previous JSONL each ≤512 KiB; report ≤256 KiB; replacement temporary
files have the same individual caps, so atomic replacement has bounded overlap.
Previous records and recovery reads are bounded. First causes survive history
saturation, with lost-timeline and chronology-complete indicators. ENOSPC,
unwritable destination and rename failure do not advance ack: the HUD shows
DEGRADED while the first cause remains available in memory. Historical write-error
count persists when writing recovers. No software can guarantee durability after
immediate power loss/kill before disk acknowledgement; even acknowledgement here
is OS write/rename success, not a power-loss/fsync guarantee.

No raw game/launcher logs, credentials, IPs, private paths, seeds, names, chat or
assets enter the recorder. Only enum/numeric fields are accepted; recovery
normalizes those fields. Planted secret/path/IP/PIN text is rejected in tests.
There is no cloud upload or analytics. Files Share is user-initiated.

## I — Bounded retries and retirement

At most three attempts per boot. After a recoverable cause, backoff is ≥2 seconds,
total diagnostic retry window <120 seconds. A retry occurs only in `section` for
a **new accepted Streaming::update result**, with a real camera and newly captured
current source/lightmap. No cached stale geometry is reused. No new streamed
candidate records NO_FRESH_MESH_AVAILABLE instead of manufacturing one.

Admission requires all three: process-wide G05 permit idle (including orphan
completion retention), Rust registry empty, Swift target dictionary empty and live
active/key/uncovered host. At most one candidate/worker/child/permit remains.
World changes, shutdown, background, resource reload, renderer/device failure,
memory warning, panic and timeout forbid retry; late stop causes survive ring
rotation. Expiry after a successful five-second reveal is cleanup, not a fabricated
failure. All three attempt histories remain in the report.
