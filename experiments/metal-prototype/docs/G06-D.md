## D — Implemented core

`src/flight_recorder.rs` in the experiment: finite typed cause/stage/emitter
fields, common Rust monotonic clock and mutex-serialized sequence/queue insertion,
per-current-attempt write-once first cause, old-ID isolation, 128-event memory ring,
64-slot nonblocking writer queue, single writer, 512KiB active/previous JSONL and
80-event report tail with first causes retained separately for three attempts.
Report replacement uses temporary file + rename. Raw error messages/user strings
are NOT accepted for serialization: allowlisted fields/numeric values only.

Admission begins an attempt only after the native registry is found idle; a busy
submission cannot reset another attempt's latch. Recording never claims GPU
success or authorizes drawing. Current setters are instrumented only partially.
Queue saturation/write errors are NOT yet surfaced to UI, first-cause durability
under saturated queues is NOT proven, crash recovery/boot IDs are NOT implemented.
These limitations prevent shipping this core as a complete flight recorder.
