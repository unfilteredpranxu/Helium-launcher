## Contract and production connection

`upload` v1 is a platform-neutral checked single-bank contract. `Source` owns
immutable pixel storage, exposes its actual generation/revision and complete
layer-major/mip-major descriptor, and checks the live producer authority.
`material_adapter::BankSource` owns an Arc to the authentic G04 snapshot and keeps
its production ticket. Its authority is the LIVE Renderer: source release,
animation revision changes, pack reload, recreation, unsupported HDR/PBR/shader
packs and unavailable observations reject. Retained historical bytes alone are
not authority. No conversion to numeric guessed generation IDs is performed.

`Binding::upload_source` captures a selected existing bank without copying pixels.
`changed_span` uses actual production changed global IDs to select a checked local
layer span. The uploader verifies all bytes OUTSIDE a partial span against its
last completed source. Missing updates across skipped revisions therefore reject
rather than authorizing a partially current atlas. Full upload remains the safe
refresh when changed layers cannot be proved. Partial mip subsets and discontiguous
span lists are not exposed; each selected layer updates its complete mip chain.

The format is RGBA8Unorm, square power-of-two, complete production mips. The
original global range, bank index, used count, allocated padding slices, split and
sprite count are retained. `Description::slice` validates mapping before subtracting
the bank's first global ID. It never truncates/wraps/substitutes a sprite.

G02 policy stays 4096 pixels and 256 allocated slices. These are conservative
baseline policy ceilings, NOT queried texture maxima or A16 RAM assumptions.
Actual baseline family, sample-count and maxBufferLength checks come from the same
G02 renderer/device. Oversize production banks (including a normal Metal split of
512) explicitly reject. A supported final bank can upload independently, but the
existing GLOBAL-ID G02 shader can draw only bank zero; nonzero-bank drawing rejects
without rewriting vertices. Small-bank tests establish no full-atlas compatibility.

## Metal ownership and completion

`TerrainRenderer::create_material` creates a private RGBA8Unorm Type2DArray with
all allocated slices and mip levels. It uses the existing G02 device/queue, not a
new renderer. `Material::upload_blocking` validates first, then stages initialized
rows in a CPU Vec and a copied shared Metal buffer. 256-byte aligned row pitches,
image sizes, offsets, complete source chains, target bounds and checked arithmetic
are preflighted. Row padding is zero. Every copy uses the real Metal buffer/texture
blit API, preserving alpha and original bytes.

The texture persists across compatible updates. Exclusive mutable access serializes
updates: there is at most one pending upload and no unbounded queue. Old and new
source owners, texture, retaining command buffer and staging owners stay live
through `waitUntilCompleted`. Even a post-commit protocol error cannot return before
the wait. Completion requires the exact command to report `Completed` AND no NSError.
Failures after encoding revoke residency; partial retry requires a completed base,
so recovery from a possibly partial write requires a full upload.

`Ticket` is a non-cloneable, one-use receipt of that exact operation, with private
owner/device/operation IDs and source identity. Internal transitions are
Prepared → Encoded → Submitted → Completed/Failed/Invalidated. There is no public
method to mark completion. CPU protocol tests simulate events privately and are
not hardware evidence. A receipt's phase describes its historical operation;
`consume_ticket` also checks current owner, operation, device generation, live
source and one-use state. Old completion cannot authorize a new resource or revision.

IDs are checked monotonic process-local nonces, not addresses or timestamps.
Renderer reconstruction creates a fresh device-owner nonce even if Metal returns
the same physical device. Release revokes receipts and drops texture/source; all
public operations have already waited, so no internal GPU work can still reference
a freed owner. The material retains the Metal device independently of the renderer.
No unsafe Send/Sync, borrowed callback or lifetime extension is introduced.

`TerrainRenderer::render_material` binds this persistent texture to the existing
G02 pipeline with the SAME mesh, depth, uniforms, lightmap and shader/oracle. It
uses the common G02 resource-layout validation, counts full resident mip payload
and retained source ownership, and skips atlas creation/staging/blits. Repeated
resident draws need no texture upload. It still waits on its own draw/readback
command. This is a worker/offscreen validation boundary, NOT a nonblocking gameplay
uploader. The production wgpu renderer and `State::gpu_current()` are unchanged.

## Memory and counters

Preflight includes full GPU mip payload, CPU staging Vec, Metal staging buffer,
copy-region metadata, new retained source and historical retained source. The
source may retain a whole multi-bank snapshot; that entire capacity is counted.
Shared source allocations are conservatively counted twice when old/new ownership
overlaps, never silently omitted. This is a safe payload upper bound, not measured
RSS/driver residency. Metal texture padding, driver objects, allocator overhead and
fixed headers are outside the explicit payload budget.

Initial create allocates one texture only after full-operation preflight. Updates
reuse it. CPU staging and Metal staging are temporary, released after the exact
completion wait. Sources are not re-copied except into padded staging required by
the blit. There is no ordinary GPU readback. `readback_for_validation` is explicit,
budgeted test/diagnostic code, reading only initialized rows after its own command
completes. The same conservative budget covers its output and scratch.

Counters report actual upload bytes committed, current texture payload,
staging/source payload high-water values, reused resources, pending operations,
failed upload allocations after owner creation, and completed uploads. Texture
creation failure returns an error before an owner exists; it is not counted as a
successful allocation or completed upload. Counters are allocation/operation
accounting, not FPS, thermal, hardware memory or latency measurements.

multiple slices/mips, last layers, alpha, partial updates, omitted changes, namespace
mapping, malformed formats/dimensions, budgets, pitches, overflow, source release,
stale revisions and private protocol transition/failure simulations. The typed
adapter test uses actual production PreparedTextures mip generation and snapshot
ownership with handcrafted inputs. It verifies exact generation/metadata/pointer
preservation and ownership after producer destruction, without claiming that a
historical source remains authorized.

The ignored native test performs actual Metal uploads and readbacks, partial
updates on the same resource, old-source release, wrong-owner rejection, receipt
one-use checks, release, and repeated resident G02 full-image oracle draws. It
fails rather than skipping if explicitly run without a native Metal device.
No CPU image is substituted for native readback.

## Usage and acceptance

On Apple, a production integration can capture `binding.upload_source(producer,0)`,
call `native.create_material(&source, producer, budget)`, then move `source` into
`material.upload_blocking(&native, source, producer, Update::Full, budget)`.
`consume_ticket` validates the exact completed receipt against the same live
producer and native owner. A later current BankSource can use `changed_span` and
a checked partial update; omitted bytes are independently checked against completed
residency. No raw Metal texture or lifetime-extended slice escapes this boundary.

**Implementation acceptance: PASS for the explicitly supported single-bank,
blocking offscreen scope**, confirmed by the final native CI results below. All ten implementation criteria have executable paths/tests:
checked source conversion, exact identity/mips, native ownership, precise receipts,
real completion, in-flight retention, checked partial layers, budgets, preserved
regressions and branch publication. Evidence establishes native Metal on the macOS
CI runner; physical iPad A16/iPadOS 27.3 execution remains NOT RUN. Full production
atlases, multi-bank G02 drawing, asynchronous gameplay upload and authentic-resource
coverage are not claimed. Minimum iOS remains 15.0; no IPA, signing or packaging.
