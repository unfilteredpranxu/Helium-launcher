## B — Actual game architecture and source trace

`entry::main_with` starts the real game/event loop after resource/bootstrap loading.
`Game` owns `World`, `Streaming`, the production Renderer and camera/player state.
`Game::update_world` calls `Streaming::update(&mut self.world)` and receives ready
SectionMesh objects plus unloaded columns. Streaming checks Done::Meshed's worker
sequence against `meshing` and rejects columns that disappeared. Resource reload
replaces Arc<WorkerContext> and clears meshing sequences; old-resource results are
freed, not accepted. Accepted meshes feed Renderer::upload immediately or wait in
the existing budgeted upload list, where newer results replace queued versions.
Streaming::free returns uploaded/stale CPU meshes to worker-side reclamation.
Renderer::remove_columns removes unloaded GPU sections.

The new hook runs on accepted results BEFORE pool reclamation, checks the column
is still loaded after the streaming sweep, and retains at most one supported
section. It does not alter the existing upload budgets, mesh pool or world data.

`Game::render_frame` builds the real Frame from camera/player/render settings.
After successful `Renderer::render(&frame)`, the new hook uses generated lightmap
and material revisions from that live Renderer. An unavailable/failed wgpu frame
revokes the diagnostic rather than authorizing old producer state. Loading/title
frames cannot dispatch a world section. No additional world generator exists.

## D — Geometry and mesh identity

The exact existing expanded_solid adapter validates real SectionMesh, 24-byte ABI,
quad topology, flags, UVs, positions, lighting and color. Translucent and packed-only
sections reject whole, rather than exporting an incomplete section. Redundant
packed storage is excluded only when its complete expanded solid stream exists.
All global sprite IDs remain unchanged. Bank-zero incompatibility rejects before
retaining CPU geometry. Empty sections never create a draw.

A bounded copy is necessary because the producer returns mesh storage to its pool
before asynchronous consumption. At most one 2MiB geometry allocation (vertex plus
index capacity) is retained; borrowed adapter validation happens before copying.
The backend then creates owned Metal buffers before GPU access. There is no
per-frame copy when disabled, and no world-sized CPU mesh mirror.

World origin exactly follows production resident::origin: x*16,
layout.min_y()+section_index_y*16, z*16, with checked arithmetic. Worker job sequences
are not exported by Streaming::update, so the bridge preserves its stale-result
filter and uses a separate checked monotonic ACCEPTANCE sequence for replacements.
It does not invent an original worker sequence or use addresses/frame times as IDs.

## E — Producer materials and real bank limits

PreparedTextures receives optional retention only for the compiled, selected,
Apple-supported mode. Capture remains the production post-device-resplit mip
pipeline. Binding::upload_source supplies the existing immutable BankSource and
actual producer generation/revision/bank metadata; original pixel/mip bytes are
Arc-shared, not regenerated or copied by the bridge.

The actual Metal production default is a 512-slice split (`adapter_requested_split`
in gfx.rs). G05 still permits <=256 allocated slices and bank-zero rendering.
This mismatch is a CONFIRMED SOURCE-LEVEL blocker, not a measured asset-run result.
The new preflight reports actual allocated/used/split/sprite counts and rejects
before copying section geometry. It never truncates/wraps/remaps a sprite.
A deterministic test uses PUBLIC production preparation to prove rejection of a
512-layer bank and acceptance of a 256-layer bank's metadata.

The existing production `HORIZON_SPRITE_SPLIT=256` developer option can legitimately
produce smaller banks; it is NOT set automatically by this integration. It may
itself reject when the full atlas cannot fit eight banks. Even with that option,
a section containing IDs outside bank zero rejects whole. HDR, PBR, shader packs,
tiled LOD and unsupported material modes are not advertised as supported.

## F — Real camera and generated lightmap

The runtime hook uses Renderer::views(frame).primary().view_proj(frame.bob*frame.spin),
including actual yaw/pitch/FOV/aspect/far-plane and pose. This is the existing
unjittered game projection, not an identity/synthetic camera or a new approximation.
Section-origin minus Frame.camera is computed in f64 before conversion to f32.
Actual physical production configuration width/height is used for the native target;
zero, oversized or over-budget targets reject. No silent target rescaling occurs.

The hook runs after update_lightmap inside the production render call. It requires
material_state.light_revision() to be initialized and opaque RGBA8 lightmap bytes,
then copies that exact fixed 1024-byte generated lightmap. Sky/block texel placement
and gamma/weather/darkness generation remain production-owned. No G02 synthetic
lightmap is used in the actual game path.

## H — Selection and fallback

Build the game with `--features helium-direct-metal`; opt in at process startup
with `HELIUM_DIRECT_METAL=one-section`. Unset/off selects the normal path. Invalid
values report actionable diagnostics; non-Apple selection rejects and retains wgpu.
With the feature absent, hooks/field/dependency are compiled out. With it present
but off, no controller, mesh retention or material observation is created.
A cargo-tree check confirms default game dependencies exclude bridge/backend.

This explicitly named diagnostic mode leaves the visible backend as wgpu. A native

claims fallback output was native. Initialization/format/budget/unsupported-resource
errors log the reason and preserve the original render result/world session.
There is no destructive restart, save change, automatic setting override or new UI.

## I — Lifecycle and authorization

One candidate and one bounded worker, no future-section queue. Same-section updates
revoke pending work; new waiting versions replace candidates. Unload, pack reload,
world replacement/exit, suspension, shutdown, material generation/revision, generated
lightmap revision and target-size changes revoke ownership. Busy work is not queued.
After one submitted attempt finishes, the controller stops for this game session.

The production Renderer cannot safely be borrowed across worker threads. A versioned
revocable CPU lease therefore retains immutable BankSource/geometry and a unique
atomic cancellation flag. The real producer validates before dispatch and rechecks
BankSource plus light revision after the worker result. Worker receipts prove only
historical bank-local GPU bytes until that final live game-thread check succeeds.
This is NOT a replacement for live producer authority or G04 global gpu_current().
New revisions cannot be authorized by old worker completion.

Existing G05 retaining commands and owned completion leases protect CPU/GPU objects
on cancellation, owner drop and timeout. The worker has a 30-second diagnostic
deadline; timeout reports failure and drops Rust pending ownership WITHOUT inventing
GPU completion. Native retained references/callback ownership keep resources alive
until actual retirement; a hung GPU keeps the single process permit occupied.

Review repaired an unload-in-the-same-update edge, missing resize binding, failed
production-frame revocation and oversized-bank retention before copy. No unsafe
Send/Sync, borrowed callback, unbounded command queue or new GPU completion protocol.
