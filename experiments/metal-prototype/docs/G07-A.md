## Epoch audit — confirmed missing render-client propagation

At baseline `Game::new` constructs Controllers for both the render client and
integrated server (only split guest excluded). `game/integrated.rs` creates a
second Game with `ExecutionRole::IntegratedServer`; server world installation (`finish_open_world`, reached from `load_world` or integrated startup) calls
`world_changed` at game.rs:13453. Render client's `remote.rs::join_server` and
client-level replacement install new streamers/worlds without that notification.
`Controller::new` initializes epoch 0; `allocate(self.world_epoch)` records that
value. Thus server epoch 1 does not prove the rendering Controller has epoch 1.
This is a source-confirmed route for the discrepancy, not private-log instance
tracing or proof that every owner event took this exact path.

Fix: only client execution roles construct a Controller. Render-client streamer
installation (join and actual new client level) calls `world_changed`; leave
revokes. Each change gets a process-unique monotonic epoch, not a save identifier.
Admission rejects no-world epoch 0. Tests verify different Controllers and new
worlds do not share epochs, and cancellation retains ownership. Old callbacks
remain keyed to exact attempt id and cannot publish a later Gate.

## Memory-pressure episode — separate from those first causes

Game's `App::memory_warning_here` emits Game cancellation; UIKit's independent
didReceiveMemoryWarning observer calls `cancelAllNativeTargets(34)` and emits
Swift context/attempt cancellations. Recorder formerly suppressed only an exact
consecutive duplicate INCLUDING emitter. Alternating those emitters reproduces
unbounded redundant terminal events: the new test failed on baseline behavior
with **745 timeline evictions for 1,000 notices**. This confirms an aggregation
defect and dual-emitter route; it does not establish why the OS sent each warning.
No recorder-to-OS feedback root cause is asserted.

Now aggregate by episode (five seconds of quiet closes an episode), retaining
first terminal notice for each exact attempt/emitter, total notice count, first/
last monotonic time and emitter mask. At most 16 episode summaries are retained;
evicted episode count is explicit. Actions are not suppressed: Game still cancels
and reduces render distance, Swift still revokes/removes views. Memory pressure
blocks retries including preattempt admission. Priority first causes remain
separate. Latest content telemetry is coalesced into current-value summary fields
so two per-frame metadata emitters cannot create another flood. Sequence gaps
from summarized updates are not counted as lost timeline events.
Episode totals/timing are persisted in the current human-readable report. Prior-
boot JSONL recovery retains the first notices and priority causes, but does not
reconstruct the aggregated episode totals from the former report; this is a
reporting limitation. Other distinct terminal causes still use the bounded ring
and its explicit loss counter, rather than an unlimited history.

The earlier HUD screenshot showing zero lost events preceded the later flood; the observations do not conflict. PREVIOUS_BOOT_INCOMPLETE is not proof of an OS crash.

The owner's later episode (~75–100s later, 256 MemoryPressure entries, 203 lost,
chronology incomplete, no write errors) is not the cause of attempts 1–3. Further
renderer/LiveContainer memory optimization is outside this milestone. Logical
budgets are not total process RSS: geometry 2MiB, charged CPU snapshots 64MiB,
native payload 192MiB, staging 16MiB, target 6M pixels, analytical three-drawable
reservation 64MiB. One candidate/worker/child and process-wide GPU permit remain.
